## 4. In plain words

- **The paper's history baselines peek at results that did not exist yet.** In LRTS, a run's "previous outcome" is taken from the previous run *by start time*. For 49.8% of runs (macro; Kafka 77.8%) that previous run was still running, and 45.8% of the "last outcome = fail" values come from such an unfinished run.
- **How much it matters.** Making exactly the same baselines respect finish times changes macro APFDc by -0.0056 for LastFail and -0.0027 for cbt_LastFail (All). A small macro change can hide larger per-project effects; see `gate2_reproduction.json` → per_project.
- **Best simple rule by subset (chosen on validation):** All: ChangedOrNewFirst, FirstFail-asof: QTF, FirstFail-old: QTF, New/Edited: ChangedOrNewFirst. These are the numbers a model must beat.
