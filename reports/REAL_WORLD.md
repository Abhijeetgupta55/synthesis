## Caveats

- **Mined bugs are reintroduced known bugs.** The revealing test usually arrived with the fix, so this measures *regression catching*: would the tests that guard a past fix have been run early?
- **The mined diff is the reverse of the fix** (only the non-test source files are restored), an approximation of the original buggy change.
- **Selection bias toward test-backed fixes**: only commits whose message says fix/bug/regression/issue and that touch both source and tests are candidates, and only reproducible ones are kept.
- **Mutants are synthetic** single-point changes; sites are drawn from covered lines, which favours the coverage-first baseline.
- The NetworkX mutant set (seed 42) contains **no negated-condition mutants**: that operator had a bug, found and fixed after the set was generated; the set was not regenerated so the logged seed still reproduces it.
- **The global model was trained on Apache CI data** (9 Java/Scala projects + TVM's Python suites), never on these repositories.
- **Short suites mean small absolute savings**; smartci's own start-up cost (imports, git diff, scoring) is paid on every run and is reported below. The value grows with suite length.
- Times in the backtest are *simulated* sums of profiled durations; GATE 5 checks them against real pytest runs.
