# DEMO SCRIPT

**smartci: predicting CI test failures to run the right tests first**

Generated by `python -m stp.reports.presentation_md`.

## The 60-second pitch (for anyone who walks up)

> "When programmers change code, a server re-runs thousands of automatic tests, often for hours, in a fixed order. If something broke, the test that notices may be near the end, so people wait. We trained a machine-learning model on 108,000 real test runs to predict which tests will fail for a given change, and run those first. Nothing is skipped. On real data, the first failure shows up after about 3% of the run instead of 34%. The honest twist: a simple rule like 'run the tests of the files you changed' is almost as good, and for brand-new failures 'fastest test first' is better. So our tool measures which order works best on your own code and recommends that."

Then press **▶ Run the race** on the *Start here* page.

## For a general audience (open day, friends, non-programmers)

- Use only *Start here* and *Break the code*. Skip the ML pipeline tabs.
- Lead with the keys analogy, then the race button, then the calculator with *their* numbers.
- Say "test" = an automatic check that the program still works; "CI" = the robot that runs all checks after every change.
- Hand out or show `reports/EXPLAINER.md`; its last section answers the usual questions (does it skip tests? is it big AI? is this a real problem?).
