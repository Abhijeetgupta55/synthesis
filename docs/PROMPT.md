2. **As-of rule.** The history for run R (project p, stage s, start t) is all runs of p with `end = start + min(build_duration, cap) ≤ t`. Pick the cap from the distribution and document it. Implement two variants, same-stage history and all-stage history with a `same_stage` indicator, and choose between them on validation.
3. **Pure feature functions** in `src/stp/features/`, shared later with smartci. Each takes plain inputs (a history object, a diff object, a test identifier) and returns numbers. No LRTS-specific I/O inside them. All features are language-agnostic:
   - **History:**
     - `n_fail_asof`
     - `days_since_last_fail_asof` (large sentinel if never)
     - `fails_last_7d`, `fails_last_30d`
     - `last_outcome_asof` (most recent finished run containing this test)
     - `n_transitions_asof`
     - `n_runs_seen_asof`

# Phase 4: smartci, the tool

Package: `src/smartci/` with console script `smartci` and a pytest plugin registered through the `pytest11` entry point. The plugin is **inactive unless** `--smartci` is passed (or `SMARTCI=1`), so installing it never silently changes behaviour.

**Scoring unit:** test **file** (a pytest module), the closest analogue of LRTS test classes. Within a file, keep pytest's original order. Optionally break files into classes when present.

1. **`gitdiff.py`:** compute the change as `git diff <base>...HEAD` plus working-tree changes. Gives a list of files and patch text. Handles renames, binary files and huge diffs (cap).
2. **`history.py`:** the repo's own CI history in `.smartci/history.parquet`.
   - `smartci record --junit report.xml --start <ts> --end <ts> [--commit SHA]` ingests a pytest JUnit XML run.
   - All history features are computed **as-of** with the same Phase 1 functions.
3. **`scoring.py`:** load `models/global` (cold-start variant if history is empty or small), build features for every collected test file, and apply the optional **per-repo adapter** (see learn). Output calibrated P(fail), expected duration, priority = P / duration, and reasons.
4. **`plugin.py`:** the `pytest_collection_modifyitems` hook. Stable-reorders items by priority. Prints a short header ("smartci: N test files ranked; top 5: …; receipt: path"). Writes a **receipt** JSON in `.smartci/receipts/`:
   - base and head SHAs, diff hash, model version, timestamp
   - per-test features, probability, priority and rank
   - after the run (via `pytest_runtest_logreport` / `pytest_sessionfinish`): each test's real outcome and duration, and the time of the first failure
5. **`explain.py` / `smartci explain`:** for the top 10, the three largest contributions as plain sentences. Use LightGBM SHAP or LR contributions. Examples:
   - "This test's file is in your change."
   - "Same package as 3 changed files."
   - "Failed 2 days ago."
   - "When `cluster.py` changed before, this test failed 4 times."
6. **`profile`:** `smartci profile` runs the full suite twice on the clean base commit with `--junitxml`. It records per-test durations, pytest's real default collection order, and the outcomes. Tests with inconsistent outcomes are marked flaky and excluded from benchmarks.
7. **`learn.py` / `smartci learn [--since DATE] [--max N]`:** mine the repo's own history for **test-backed bug fixes**.
   - **Candidate commits:** they touch both non-test source files and test files, and are flagged by message keywords (fix, bug, regression, issue refs) or linked issues.
   - **Reproduce each one:**
     1. check out the fix commit
     2. restore only the *source* files from the parent
     3. run the touched test files
     4. **keep only if ≥ 1 test fails**
     5. restore cleanly
   - Store each bug in `.smartci/bugs.jsonl`: fix_sha, parent_sha, date, source diff (reverse of the fix), failing test nodeids, run log path.
   - Log every exclusion with its reason (no failure, error at collection, timeout, flaky, needs other dependencies).
   - Use the current pinned environment, and report how many old commits couldn't run under it.
   - **Per-repo adapter:** split the mined bugs chronologically (older 60% adapt, newer 40% evaluate). Fit a small regularized LR stacker on [global model logit, coverage signal if available, repo-level features], or skip it if there are fewer than about 20 adapt bugs. **Never evaluate on adapt bugs.**
8. **Optional coverage signal:** `smartci coverage-map` runs the suite once under coverage with dynamic contexts on the base commit, mapping test file → covered source lines. Feature: `covers_changed_lines`.
9. **Built-in baselines everywhere:** pytest default order, random, fastest-first, recently-failed-first (when history exists), changed-files-first (name/path match), and **coverage-first** (tests covering changed lines; this is what tools like pytest-testmon do) when a coverage map exists. **If smartci does not beat the best simple baseline on the user's data, every report says so and recommends that baseline.**
10. **`backtest.py` / `smartci backtest [--set mined|mutants|both]`:** for every **held-out** bug, compute time-to-first-failure and APFDc for each ordering.
    - Uses real per-test durations from `profile`, pytest's real default order, and the bug's real failing tests.
    - Output: `.smartci/backtest.json` plus a markdown table with GitHub commit URLs (when the remote is GitHub), medians, win/tie/loss counts against each baseline, and bootstrap CIs.
    - **Losses are listed, not hidden.**
11. **`mutate.py` / `smartci mutate --n N --seed S`:** a never-seen-bug benchmark.
    - Generate seeded random single-point mutants with Python `ast`: comparison and boolean operator swaps, `+`/`-` swaps, off-by-one on integer constants, `return x` → `return None`, negated conditions. Only in source lines covered by the suite (from the coverage map).
    - Keep mutants killed by ≥ 1 **existing** test (run only the tests that cover that line to decide). The diff for each mutant is the mutation.
    - Record the kill-test nodeids.
    - Caveat to state: mutants are small and synthetic, and selecting covered lines favours the coverage-first baseline.
12. **`compare.py` / `smartci compare --bug <fix_sha|mutant_id|working-tree>`:** really run `pytest -x -p no:cacheprovider` in default order and with `--smartci`. Print both pytest outputs, the FAILED line and the real elapsed seconds.
    - Two modes: **sequential** (accurate timings; default) and **side-by-side** (two concurrent subprocesses, for show; note CPU contention).
    - Uses two **git worktrees** so the runs never interfere.
13. **`shadow.py` / `smartci shadow` + `smartci report`:** for CI. Computes and stores smartci's ranking **without changing the order**, records the real outcomes, and after N failing runs reports "would have surfaced the first failure X min earlier (median); better on A, worse on B" against the user's current order and the simple baselines.
14. **GitHub Action:** `action.yml` (composite) plus an example workflow `.github/workflows/smartci-compare.yml` with two parallel jobs on the same commit:
    - `default`: `pytest -x --junitxml=…`
    - `smartci`: `pytest -x --smartci --junitxml=…`

    Each job prints the start time, the first-failure time and the end time; history is persisted via `actions/cache`. Also a shadow-mode example workflow.
15. **README "smartci" section:** install, the five commands, the safety statement ("smartci never skips tests; worst case is no speed-up"), how to read a receipt, what the baselines mean, limitations.
16. **Tests:** unit tests for diff parsing, feature parity between the LRTS pipeline and smartci on a small synthetic case (**same inputs → same feature values**), plugin ordering stability, receipt schema, and the mutate/learn harness on a tiny fixture repo created in a temp dir.

**GATE 4:** `pip install -e .` in a fresh venv. Then `smartci profile`, `learn --max 5`, `backtest` and `compare` run end-to-end on a small fixture repo and on NetworkX (next phase) on Windows.

   - selection bias toward test-backed fixes
   - mutants are synthetic
   - the global model was trained on Apache data (JVM + TVM Python)
   - a short suite means small absolute savings; the value grows with suite length
